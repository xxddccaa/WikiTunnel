# 手工验收

测试前确认 VPN、目标数据库、远端主机、SSH Agent/Keychain 和 autossh 状态。执行前可用 `ssh remote-host true` 做只读认证检查。

1. **正常连接**：新建远端主机隧道，远端 15432 空闲，点击启动；检查状态变为已连接、autossh/ssh PID 有值、远端端到端检查为 ok。
2. **无监听时启动**：先 `ssh remote-host "ss -ltnp 'sport = :15432'"` 确认输出为空，再启动，确认出现远端监听并且日志无端口冲突。
3. **旧会话占用**：保留一个旧转发占用 15432 并断开目标网络，再启动新配置；确认显示“远端端口冲突”、重试暂停，清理按钮先展示详情。
4. **已有健康隧道**：保持一个可端到端访问的 15432，点击启动；确认提示“已有健康隧道”，`pgrep` 不新增本 profile 的 autossh。
5. **OpenVPN 断开**：隧道建立后断开 VPN；确认 DNS 或目标数据库 TCP 检查失败，状态变为 VPN/目标不可达，不连续刷相同错误日志。
6. **VPN 恢复**：恢复 VPN，等待自动诊断或点击测试；确认状态恢复，重连次数增加。
7. **SSH 认证失败**：在临时 profile 中使用不存在的 key 或不可用 Agent；确认状态为错误、认证检查失败，进程不持续重启。
8. **目标数据库 5432 不可达**：临时把目标端口改为一个不可达端口，确认 DNS 成功但目标数据库 TCP 失败，autossh 不启动。
9. **睡眠唤醒**：连接正常时合盖数分钟再唤醒；确认日志出现系统唤醒诊断，状态重新校验。
10. **应用重启接管**：启动隧道后关闭 WikiTunnel 后端，再运行 `./run.sh`；确认 PID 与启动时间能恢复，未启动第二个 autossh。
11. **停止边界**：记录应用启动的 PID 和一个无关 SSH 进程 PID，点击停止；确认只终止本 profile 的进程组，无关 SSH 仍存在。
12. **日志脱敏**：在测试日志副本中加入 `password=test` 和伪私钥块，刷新页面与复制诊断；确认界面和剪贴板不包含原值。

清理测试：只在确认唯一 sshd PID、地址和端口完全匹配后操作；任何不确定情况都使用页面给出的手工命令。
